## Licensing boundary and release gate

L has top-level `LICENSE.txt` (LGPLv3). `Keys.cs` has no separate file-level
license, attribution, derivation or origin statement beyond usage comments.
Repository licensing covers the reference as published; it does not establish
that every embedded third-party constant was contributed with authority.
The OpenOrbis fork at `92a4e7f8e5914cb06b52ba3ae6b0675da438a051` shares
lineage; repeating values there is not independent provenance. The pinned
flatz reader has no established top-level license grant; do not copy its
source/constants or redistribute bundled libraries as a workaround.

The optional harness compiles an external clean L checkout for **local test use**,
with one external PFSC adaptation already documented by the extraction oracle.
No upstream implementation/constants, generated DLLs or packages are vendored,
linked into Rust releases or approved for distribution. Redistribution of any
adapted reference would require its own LGPL compliance review, source/notices
and review of bundled material. This is an engineering inventory, not legal advice.

Before adding native writer constants: record each required value's original
source and authority, exact source pin/file, public-versus-secret classification,
applicable license/permission and explicit distribution decision. Use maintained
crypto primitives, independently implement format algorithms, and keep constants
separate from copied reference code. If rights remain unresolved, stop that
profile or design an explicitly reviewed local-input policy; do not silently
expand the existing offline/public-fake-key RSA exception to user secret keys.

**Result:** required symbols and historical leads source-confirmed; complete
provenance/distribution gate **not cleared**. Executed synthetic oracle proves
reference interoperability, not legal provenance, authentic signing or console
acceptance. No full-update binding inference follows from any of these inputs.
